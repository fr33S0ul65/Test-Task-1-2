# AI-інструменти для підтримки клієнтів

Тестове завдання на позицію AI Ops Specialist: два прототипи для команди підтримки астрологічного застосунку з підписками й платними чатами з експертами.

| | Що робить | Статус |
| --- | --- | --- |
| **Task 1 — класифікатор тікетів** | За текстом звернення повертає категорію, пріоритет, наступний крок і ознаку, чи потрібна людина | Готово |
| **Task 2 — асистент для агента** | Summary звернення українською, три варіанти відповіді різного тону мовою клієнта, цитата з бази знань, яку код перевіряє дослівно | Готово |

Обидва інструменти доступні в простому веб-інтерфейсі (Streamlit) з двома вкладками.

## Як переглянути без запуску

Запускати код не обов'язково: усі результати вже в репозиторії.

- `eval/results/` — кожен прогін: `.md` з таблицею «тікет → очікувано → факт» (для асистента — ще й повні тексти відповідей) і `.json` з усіма деталями.
- `docs/` — опис рішень, оцінки й обмежень (посилання нижче).
- Історія комітів показує послідовність: тестові дані закомічені до першого запуску, кожна версія промпту — до прогону на ній.

## Запуск

Потрібні Python 3.10+ і **власні** ключі API Anthropic та OpenAI (OpenAI — для пошуку в базі знань і для порівняння моделей). Ключів у репозиторії немає: їх треба вписати у файл `.env`, який git ігнорує.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env        # впиши свої ключі в .env
```

Веб-інтерфейс:

```bash
.venv/bin/streamlit run app.py
```

Окремо з командного рядка:

```bash
# класифікувати один тікет
.venv/bin/python -m src.classify "I was charged twice for my weekly plan this morning."

# summary і варіанти відповіді для одного тікета
.venv/bin/python -m src.assistant "I was charged twice for my weekly plan this morning."

# прогін оцінок
.venv/bin/python eval/run_eval.py --provider anthropic --model claude-haiku-5-5 --prompt v3 --effort medium
.venv/bin/python eval/run_eval.py --provider anthropic --model claude-haiku-5-5 --prompt v3 --effort medium \
    --tickets data/ticketsHoldout.json --holdout only
.venv/bin/python eval/run_assistant.py --prompt v3
```

Для моделей OpenAI: `--provider openai --model gpt-6-luna`. Прапорець `--no-cache` вимикає кешування промпту.

Один прогін оцінки на фінальній моделі коштує менше цента.

## Структура

```
app.py                      веб-інтерфейс: класифікатор і асистент
src/llm.py                  єдиний шар виклику моделей і embeddings, повтори при збоях
src/classify.py             класифікатор: промпт → модель → перевірка JSON → fallback
src/kb.py                   база знань: embeddings, кеш векторів у .cache/, пошук
src/assistant.py            асистент: пошук → summary і три тони → перевірки цитати й мови
src/pricing.py              ціни моделей і розрахунок вартості
prompts/classify_v1..v3.txt версії промпту класифікатора
prompts/reply_v1..v3.txt    версії промпту асистента
data/ticketsTest1.json      16 тестових тікетів класифікатора з очікуваними відповідями
data/ticketsHoldout.json    5 прихованих тікетів (на них промпт не підганявся)
data/assistantTickets.json  10 тестових тікетів асистента з очікуваними статтями
data/knowledge_base/        20 статей симульованої бази знань вигаданого продукту MyTestBase
eval/run_eval.py            оцінка класифікатора
eval/run_assistant.py       оцінка асистента
eval/show_next_steps.py     next_step моделі поруч з очікуваним, для ручного перегляду
eval/results/               результати всіх прогонів
```
